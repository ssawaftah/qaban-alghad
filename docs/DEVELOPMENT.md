# دليل التطوير والبناء والاختبار

## الأدوات

المشروع C# وWinForms على .NET Framework 4.5.1. لا توجد مكتبات NuGet خارجية لازمة للتطبيق الحالي. المراجع: System وSystem.Core وSystem.Windows.Forms وSystem.Drawing وSystem.Web.Extensions وSystem.Security.

على Windows استخدم مترجم .NET Framework المثبت أو Visual Studio مع حزمة استهداف4.5.1. توفر Runtime4.8 لا يعني توفر reference assemblies4.5.1 لمشروع MSBuild؛ إذا ظهرت MSB3644 فثبّت developer/targeting pack المناسب من Microsoft أو استخدم مسار البناء المباشر الموثق، ثم تحقق على جهاز الهدف. لا تغيّر TargetFrameworkVersion لمجرد تجاوز خطأ أدوات دون تقييم التوافق.

## بناء Windows المرجعي

```powershell
.\scripts\build.ps1
```

ينشئ `out/QabanAlGhad.exe` ثم مشروع الاختبارات المنفصل. يتوقف عند خطأ بناء أو اختبار. لا يشغّل التطبيق على القبان تلقائيًا، ولا يقرأ COM في الاختبارات. العلم `-SkipTests` متاح للتشخيص المحلي فقط؛ لا تستخدمه لإعلان إصدار مختبر.

```powershell
.\out\QabanAlGhad.Tests.exe --self-test
.\out\QabanAlGhad.Tests.exe --dual-test
.\out\QabanAlGhad.Tests.exe --integration-test
```

الاختبار الأخير يستخدم `HttpListener` وقد يحتاج سماح Windows لحجز URL محلي. لا تعطل جدار الحماية أو تشغّل التطبيق الإنتاجي كمسؤول لمجرد تشغيل اختبار. مهمة Ubuntu مخصصة لهذا الاختبار وتعمل على loopback.

`QabanAlGhad.sln` يوفر مشروع التطبيق ومشروع الاختبارات، والمخرجات إلى `out/`. لا تبنِ Debug وRelease في الوقت نفسه إلى هذا المجلد المشترك. السكربت هو مسار التغليف المرجعي الحالي.

## اختبار Linux/Mono

```bash
bash scripts/test-mono.sh
```

يلزم Mono مثبت من مستودع نظام موثوق. يتيح المتغير `QABAN_MONO_ROOT` استخدام حزمة Mono محلية في بيئات التطوير. ليس هذا برنامج تثبيت للمستخدم النهائي. لا ينقل Mono إلى جهاز الشركة ولا يجعل WinForms تطبيق Linux مدعومًا.

## منع تكرار MissingMethodException

النسخة التي بُنيت بمرجع Mono اختارت `String.Split(char, StringSplitOptions)`؛ هذا الاستدعاء غير متوفر في بيئة .NET Framework التي شغلت القبان، فنجحت الاختبارات على Mono وفشلت القراءة على الجهاز. المصدر الآن يحدد `Split(new char[]{','})` صراحة. اختبار IL يفحص الاستدعاء في التجميعة المبنية نفسها. لا تختصره إلى `.Split(',')` أثناء التنسيق دون تحقق من مرجع البناء.

هذا الفحص يعالج الانحدار المعروف، وليس شهادة شاملة بأن كل API في أي تغيير لاحق مدعوم. بناء Windows الأصلي وفحص جهاز الهدف مطلوبان. لا توزع EXE بُني على Mono وحده كإصدار نهائي.

## التحقق من واجهة المستخدم

شغّل النسخة المرشحة أولًا بوضع مراقبة دون تفعيل إرسال الوزن. تحقق من المحاذاة الوسطية، العربية، صغر النافذة، الأزرار، وعدم ظهور أي عنصر خاص بالوجهة الخلفية أو «رد الخادم». بعد ذلك اختبر COM الحقيقي ثم أرسل وزنًا فعليًا وتحقق من الموقعين.

لم يتم إجراء فحص بصري أو فتح COM فعلي للهيكل الجديد في بيئة Linux الحالية. لا تكتب في ملاحظات الإصدار أنه معتمد ميدانيًا قبل هذا الفحص.

## قبل إرسال التغيير للمراجعة

راجع فرق الملفات، حدّث دليل الجزء المتغير، شغّل الفحوص المناسبة، وتحقق من عدم وجود settings.json أو تهيئة خاصة أو مفاتيح أو سجلات. استخدم بيانات وهمية واضحة في أمثلة API. لا تضف package أو dependency كبيرة لإصلاح ترتيب ملفات يمكن حله داخل الكود الحالي.
