# التحديث من داخل البرنامج — 0.10

## التنفيذ الحالي

يفحص البرنامج أحدث GitHub Release رسمي عند فتح النافذة، ويتيح «التحقق من التحديثات» في الإعدادات. يظهر «تحديث البرنامج» فقط إذا توفر إصدار أعلى. التنزيل لا يوقف القبان؛ التثبيت يتطلب موافقة المستخدم، ثم يوقف القراءة والإرسال ويغلق البرنامج ويعيد فتحه. خيار الإرسال لا يُفعّل تلقائيًا بعد إعادة التشغيل.

## مصدر الثقة

المصدر مثبت في الكود: `ssawaftah/qaban-alghad`. تُقرأ البيانات من `https://api.github.com/repos/ssawaftah/qaban-alghad/releases/latest` عبر HTTPS دون أي رمز دخول. يجب أن تكون النسخة منشورة ومستقرة وغير draft/prerelease، واسم الحزمة ورابطها تابعين للإصدار نفسه. تُرفض نسخة مساوية أو أقدم.

بصمة SHA256 وحجم الحزمة يأتيان من بيانات Release asset التي تحسبها GitHub، وليس من ملف داخل ZIP. لا يقبل البرنامج حزمة بلا digest. يسمح بتحويل التنزيل فقط إلى نطاقي GitHub الرسميين `release-assets.githubusercontent.com` و`objects.githubusercontent.com`؛ لا يسمح بتحويل API. لا يُعطّل TLS ولا يستعمل cookies أو PAT.

**هذا تحقق يعتمد على HTTPS وسلطة ناشر المستودع وحماية حساب GitHub، وليس توقيعًا مستقلاً بمفتاح خاص مثبت داخل التطبيق.** استُبدل تصميم البيان المنفصل الموقع بهذا العقد لتجنب توليد مفاتيح نشر خاصة وتوزيعها أو تضمين أسرار في العميل. عند اختراق حساب الناشر نفسه يمكن نشر إصدار خبيث؛ SHA256 لا تحمي من ناشر مخوّل خبيث. يمكن إضافة Authenticode أو توقيع مستقل في تطوير لاحق دون الادعاء أنه موجود الآن.

## التنزيل والتحقق

حد الحزمة32MiB. مهلة الفحص12 ثانية والتنزيل120 ثانية. لا تدخل هذه العمليات في Tick أو OutputChannel. الملف المؤقت يُحذف عند فشل النقل أو البصمة. بعد التحقق يُفك ZIP في staging منفصل، ويُرفض root خاطئ أو مسار متداخل أو traversal أو ملف غير معروف أو مكرر أو حزمة ناقصة. فك ZIP ينشئ ملفات عادية فقط؛ لا ينشئ symlinks، وتُرفض إشارة symlink عند توفرها في Runtime. حد الملفات20 وحد الحجم المفكوك32MiB.

لا يُكتب settings.json أو Returns.setup.json أو AppData. الملفات التي يستبدلها المثبت حصراً: `QabanAlGhad.exe` وconfig الخاص به و`QabanAlGhad.Updater.exe` وconfig الخاص به.

## التثبيت والاستعادة

الأداة المستقلة تُنسخ إلى `.qaban-update/<guid>/runner.exe` كي لا تستبدل نفسها وهي تعمل. تنشئ نسخة كاملة من الملفات الأربعة في old قبل أي تعديل، وjournal ثابتاً في `.qaban-update.json`. يحتوي token وstage وstate. يُرفض stage خارج مجلد التطبيق أو مجلد reparse. يستخدم المثبت mutex خاصاً بمسار التطبيق لمنع مثبّتين متوازيين.

بعد خروج عملية البرنامج الصحيحة تُستبدل كل ملفات Runtime عبر ملف مؤقت كامل وFile.Replace، مع flush، بدل الكتابة فوق EXE مباشرة. journal يُحدّث قبل بدء الاستبدال. النسخة الجديدة تبدأ بتذكرة محلية تطابق journal، وتكتب إقرار الجاهزية بعد ظهور MainForm. إذا خرجت أو لم تؤكد خلال30 ثانية يستعيد المثبت النسخة السابقة ويعيد فتحها. لا يعد إقرار الجاهزية دليلاً على اتصال COM أو سلامة خادم الشركة؛ هو فحص بدء البرنامج فقط.

إذا انقطع المثبت، يكتشف التشغيل التالي journal ويشغل runner للاستعادة قبل متابعة التشغيل. ملفات old تبقى للرجوع اليدوي ولا تحذف تلقائياً. إذا تعطلت وسائط التخزين أو ملفات النسخة الاحتياطية نفسها، يلزم الرجوع للحزمة السابقة يدويًا؛ لا يوجد ضمان ضد تلف القرص.

يجب أن يكون مجلد تثبيت البرنامج قابلاً للكتابة. لا يطلب التطبيق صلاحيات مدير ولا يغير سياسات Windows. فشل التنزيل يترك القراءة كما هي؛ فشل التثبيت بعد الموافقة قد يترك البرنامج متوقفًا إلى أن تُحل مشكلة الملفات أو الاستعادة.

## النشر القادم

حدّث VERSION وAssemblyInfo وRELEASE_NOTES. عند push إلى main يبني CI الحزمة ويختبر Windows وHTTP، ثم ينشر Release عبر صلاحية contents:write لمهمة نشر منفصلة فقط. ينشر draft مع الحزمة أولاً ثم يحوله إلى latest. الرقم المنشور لا يُستبدل؛ يلزم رفع رقم جديد. نسخ الإنتاج العامة لا تتضمن رموز الربط.

الاختبارات لا تفتح منفذ الميزان أو ترسل أوزانًا إلى خادم الشركة. تجربة الجهاز الحقيقي بعد التثبيت التمهيدي تبقى مطلوبة للتحقق من بيئته وصلاحيات المجلد وتعريف المنفذ.
