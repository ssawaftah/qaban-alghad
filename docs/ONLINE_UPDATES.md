# تصميم التحديثات عبر الإنترنت — لم ينفذ بعد

## الهدف

تثبيت نسخة تمهيدية واحدة يدويًا، ثم إتاحة ترقية البرنامج من داخله في الإصدارات التالية، مع بقاء إعدادات القبان وبيانات الربط محفوظة. المستخدم يوافق على التثبيت؛ لا يغلق البرنامج نفسه أثناء وزن سيارة.

الكود الحالي لا يتحقق من تحديثات ولا ينزلها ولا يثبتها. لا يوجد Updater.exe ولا مفتاح توقيع مثبت ولا عنوان بيان نهائي. هذا المستند تصميم تنفيذي ومعايير قبول، وليس وصفًا لميزة مكتملة.

## تجربة المستخدم المقترحة

الفحص التلقائي يعمل في الخلفية عند الفتح، مع خيار «التحقق من التحديثات» في الإعدادات. عند توفر إصدار جديد يظهر «تحديث البرنامج» فقط دون إضافة شروحات دائمة إلى الشاشة الرئيسية. إذا انقطع الإنترنت لا تظهر رسائل متكررة ولا يتأثر مسار القبان.

يمكن تنزيل الحزمة أثناء استمرار البرنامج. التثبيت يحتاج إيقاف القراءة والإرسال صراحة ثم انتظار إغلاق الطلبات والمنفذ. إعادة فتح التطبيق بعد التحديث لا تعني تفعيل الإرسال دون قرار المستخدم؛ يجب الحفاظ على قواعد الأمان التشغيلية القائمة.

## الملفات المخطط إضافتها

| المكوّن المقترح | مسؤوليته |
| --- | --- |
| `Application/Updates/UpdateCoordinator.cs` | تنسيق الفحص والتنزيل والتثبيت دون الاعتماد على قارئ المنفذ |
| `Infrastructure/Updates/ManifestClient.cs` | جلب البيان بمهلة وحد حجم وHTTPS |
| `Infrastructure/Updates/ManifestVerifier.cs` | التحقق من التوقيع والمصدر والإصدار |
| `Infrastructure/Updates/PackageDownloader.cs` | ملف مؤقت وحد حجم وبصمة SHA256 |
| مشروع منفصل `QabanAlGhad.Updater` | استبدال الملفات بعد خروج التطبيق، والاستعادة عند الفشل |
| اختبارات Updates منفصلة | العبث، الانقطاع، المسارات الخبيثة، الرجوع، والصلاحيات |

لا تضع تنفيذ updater داخل `Tick` أو `Protocol.Parse`. له مهلة وإلغاء وحالة مستقلة؛ فشل GitHub لا يجب أن يوقف HTTP الخاص بالأوزان.

## عقد بيان مقترح

```json
{
  "schemaVersion": 1,
  "version": "0.9.4",
  "minimumUpdaterVersion": "1.0.0",
  "packageUrl": "https://github.com/OWNER/REPOSITORY/releases/download/v0.9.4/QabanAlGhad-0.9.4.zip",
  "sha256": "REPLACE_WITH_64_HEX_CHARACTERS",
  "sizeBytes": 123456,
  "notes": "وصف موجز للتغييرات",
  "signature": "BASE64_SIGNATURE_OF_CANONICAL_UNSIGNED_FIELDS"
}
```

هذا مثال غير صالح للنشر. يلزم تحديد canonical serialization بدقة قبل التوقيع، وتثبيت مفتاح تحقق عام داخل التطبيق. SHA256 وحدها تكشف التلف، لكنها لا تثبت الناشر إذا عُدّل البيان والحزمة معًا. المفتاح الخاص لا يدخل المصدر أو الحزمة أو سجلات CI؛ لا تنشئه أو تبدله عشوائيًا من جهاز مستخدم.

## مصدر التنزيل والخصوصية

إن كان المستودع عامًا، استخدم Release assets خالية من بيانات الربط. إن كان الكود خاصًا، اختر مستودع توزيع عام منفصل للحزم أو قناة مصادقة مخصصة. لا تضع GitHub PAT داخل EXE ليصل إلى مستودع خاص؛ يمكن استخراج الرمز من جهاز العميل.

ثبت قائمة نطاقات ومسارات تنزيل مسموحة. لا تتبع عنوانًا عشوائيًا داخل البيان إلى جهة أخرى، ولا تقبل downgrade صامتًا أو إصدارًا أقل من الحد الآمن. GitHub قد يعيد توجيه Release assets إلى نطاق CDN رسمي؛ يجب توثيق السماح المحدد والتحقق من كل انتقال.

## معاملة التثبيت

1. تنزيل الحزمة إلى مجلد staging منفصل، لا إلى ملفات التشغيل مباشرة.
2. التحقق من البيان والتوقيع والحجم والبصمة قبل استخراجها.
3. رفض traversal والمسارات المطلقة وsymlinks وإدخالات ZIP المكررة أو غير المسموحة.
4. تجهيز خطة استبدال بملفات التطبيق المعروفة فقط، دون AppData أو settings أو التهيئة الخاصة.
5. موافقة المستخدم وإيقاف القراءة ثم خروج التطبيق، مع التحقق من PID ومسار التطبيق.
6. إنشاء نسخة رجوع محلية وحفظ journal للمرحلة الحالية قبل كل نقل مؤثر.
7. استبدال ملفات التطبيق بعد زوال الأقفال، ثم تشغيل النسخة الجديدة.
8. تحقق بدء التشغيل باستجابة محدودة؛ عند الفشل استعد النسخة السابقة وتجنب حلقة إعادة التحديث.

الاستعادة عبر انقطاع الكهرباء تحتاج journal وتعاملًا واضحًا مع التثبيت غير المكتمل؛ نسخ ملف احتياطي وحده لا يضمن الرجوع. إذا كان المجلد غير قابل للكتابة، يتوقف التثبيت برسالة واضحة بدل طلب صلاحيات مدير تلقائيًا. استخدام مجلد قابل للكتابة للمستخدم قرار تثبيت يسبق الإطلاق.

## مراحل التنفيذ ومعايير القبول

| المرحلة | معيار اكتمالها |
| --- | --- |
| اعتماد المستودع وقناة الإصدارات | مالك وعنوان نهائيان، حزم خالية من الأسرار، وسياسة أرقام |
| الفحص فقط | مقارنة إصدارات صحيحة، timeout، العمل دون الإنترنت، منع downgrade |
| تنزيل موثوق | توقيع وبصمة وحجم، رفض حزمة معدلة، وحدود استخراج |
| updater مستقل | قفل ملفات، إغلاق COM، إذن تثبيت، حفظ إعدادات، journal ورجوع |
| تجربة جهاز الشركة | وزن فعلي قبل وبعد، إرسال إلى النظامين، فصل إنترنت وكهرباء تجريبي مأمون |
| النشر | تثبيت النسخة التمهيدية يدويًا، ثم نجاح تحديث لاحق حقيقي من داخلها |

لا تعتبر الميزة مكتملة حتى تنجح ترقية بين إصدارين فعليين على Windows مع اختبار الفشل والرجوع. التحديث الخادمي لموقع المرتجعات يبقى مسارًا مختلفًا ولا يحتاج حزمة EXE.
