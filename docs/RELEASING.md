# بناء ونشر الإصدارات

## الحالة الحالية

هذا المستودع يجهز بناءً آليًا وحزمة خالية من الأسرار. لا يوجد نشر آلي إلى GitHub Releases ولا Updater يعمل داخل البرنامج بعد. مهمة `verify.yml` تتحقق وتنتج Artifact فقط؛ Artifact مؤقت خاص بسير العمل ليس رابط تحديث دائمًا للمستخدم.

## سياسة الأرقام

`VERSION` يحتوي رقمًا ثلاثيًا، مثل0.9.3. حدّث معه AssemblyVersion وAssemblyFileVersion في `Properties/AssemblyInfo.cs`، وسجل التغيير في CHANGELOG.md. سكربت التغليف يرفض اختلاف أول ثلاثة أجزاء من إصدار EXE عن VERSION.

## الإجراء المرجعي

1. أنشئ فرعًا للتغيير وراجع اختبارات Windows وHTTP.
2. اختبر الحزمة على Windows وقراءة القبان قبل اعتماد إصدار إنتاجي.
3. حدّث الإصدار وسجل التغيير ووثائق السلوك المتغير.
4. شغّل `scripts/package.ps1`؛ يعيد البناء والاختبارات ثم يخرج ZIP في dist.
5. افحص محتويات ZIP: EXE وconfig وأيقونة وStart.cmd ودليل المستخدم وSHA256.json فقط.
6. أنشئ Tag باسم `v<version>` وإصدار GitHub بعد اجتياز المراجعة. لا يكفي تعديل source وحده.
7. ارفع الحزمة الخالية من الأسرار، وأرفق ملاحظات التغيير وحدود التحقق.
8. عند تنفيذ Updater مستقبلًا، حدّث البيان الموقع في النهاية وبعد اكتمال رفع الحزمة.

## التغليف الخاص

يجب أن تبقى تهيئة الجهاز خارج الإصدار العام. إذا احتجت حزمة خاصة لمرة واحدة، يتم تسليم ملف التهيئة بقناة خاصة معروفة وإضافته محليًا. لا ترفع `Returns.setup.json` إلى Release عام أو workflow artifact. لا يمكن إخفاء سر إنتاجي بوضعه في مستودع خاص ثم نسخه إلى حزمة عامة.

## الرجوع

حاليًا الرجوع يدوي بتشغيل الحزمة السابقة بعد إغلاق الجديدة، مع الحفاظ على AppData وعدم حذف الإعدادات. نسخة0.9.2 هي آخر نسخة أكد المستخدم عملها قبل هذا النقل. لا توجد بعد معاملة تثبيت أو رجوع تلقائي؛ متطلباتها موثقة في ONLINE_UPDATES.md.

## ما الذي تحقق محليًا؟

البنية الجديدة اجتازت195 تحققًا باستخدام Mono، وشملت اختبارات تفحص EXE التطبيق المشار إليه من مشروع الاختبارات. ملفات PowerShell وWindows workflow ومشروعات Visual Studio جاهزة للمراجعة، لكن تشغيلها على Windows/CI بعد رفع المستودع ما زال مطلوبًا. لا تنشر إصدارًا مستخدمًا استنادًا إلى الفحص المحلي وحده.
