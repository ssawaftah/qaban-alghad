# عقود الربط والإرسال

## النظام الأساسي

العنوان الفعلي يؤخذ من `Settings.Endpoint` المحفوظ على الجهاز. القيمة الافتراضية في المصدر تشير إلى `app.circlessoft.com:9083`؛ استُخدم أيضًا `cloud.circlessoft.com:9083` أثناء التشخيص السابق. هذان اسمان مختلفان، ولا يثبت تشابه المسار أنهما نفس الخدمة. لا تبدل عنوان جهاز يعمل لمجرد إنشاء مستودع جديد.

```http
POST /api/store_weight_scale
Content-Type: application/json
Accept: application/json
```

```json
{"company_id":"1","weight_scale":"-20"}
```

القيمتان نصيتان في عقد النظام الأساسي الحالي. رقم الشركة يُتحقق منه كأرقام. الرمز Bearer اختياري ويضاف فقط إذا كان مُهيأ لهذه الوجهة. حساب دخول الموقع ليس بديلًا تلقائيًا عن API token، وملفات cookie الخاصة بالمتصفح لا تنتقل للبرنامج.

إقرار النجاح المعروف حاليًا:

```json
{"success":"Weight scale updated successfully"}
```

سبق أن رد خادم الشركة بـHTTP500 عند تكرار وزن ثابت رغم ظهور الوزن بالموقع. لا يفترض البرنامج أن كل HTTP500 نجاح، ولا يخفي معلوماته التشخيصية. «تم الإرسال» تعني كتابة الجسم فقط. معالجة المشكلة الخادمية الحقيقية تحتاج مراجعة كود خادم الشركة إن أتيحت صلاحيته.

## الوجهة الثانية: القراءة المباشرة للمرتجعات

```http
POST https://qaban-113.pages.dev/api/scale/weight
Authorization: Bearer <device-token>
Content-Type: application/json
```

```json
{"weightKg":-20,"sampledAt":"2026-11-10T10:00:00.0000000Z"}
```

`weightKg` رقم JSON، لا نص. `sampledAt` وقت آخر وصول صالح من الميزان بالـUTC؛ لا تعِد ختم عينة قديمة بوقت جديد لمجرد إعادة إرسالها.

إقرار النجاح يجب أن يحتوي `accepted:true` ووزنًا رقميًا مطابقًا للعينة المرسلة. القيم السالبة والصفر مدعومة في API الموقع بعد تحديث 7ab68e0. النطاق الخادمي المسموح ‎-200000..200000 كغ. البرنامج لا يحوّل السالب إلى صفر ولا يستخدم القيمة المطلقة.

| الرد | المعنى الخادمي |
| --- | --- |
| 200 + accepted:true | قُبلت القراءة |
| 400 | جسم/وزن غير صالح أو خارج النطاق |
| 401 | رمز غير صالح |
| 409 | عينة أقدم من المخزنة |
| 422 | توقيت قديم أو غير صالح أو بعيد في المستقبل |
| 503 | مفتاح استقبال الخادم غير مهيأ |

الموقع يقبل تكرار القيمة ويحدّث وقتها. يتحقق من عمر 15 ثانية للعينة وحد مستقبل 30 ثانية؛ أما حداثة برنامج القبان المحلية فافتراضيًا 3000ms. هذه حدود مختلفة لخدمتين مختلفتين. قراءة الموقع تتطلب جلسة دخول في `GET /api/scale/latest`.

## النقل المشترك

- HTTPS فقط في إعدادات الإنتاج؛ loopback HTTP متاح للاختبارات عبر علم داخلي.
- TLS1.2 وUser-Agent تعريفي `QabanAlGhad/0.9` في الكود الحالي؛ هذا رقم عميل بروتوكول تاريخي وليس مصدر رقم الإصدار المعتمد.
- لا تتبع redirects تلقائيًا، حتى لا يُفسّر HTML صفحة login كنجاح API.
- مهلة الطلب لا تتجاوز 8000ms ولا الوقت المتبقي لحداثة العينة.
- حد قراءة الرد 8192 حرفًا، وملفات التشخيص لا تسجل Authorization header.
- لا يوجد retry queue. المحاولة التالية تستخدم أحدث قراءة صالحة.
- يحترم `Retry-After` الرقمي حتى حد 300000ms لكل وجهة مستقلة.

## حدود المسؤولية

استقبال وزن سالب للعرض المباشر لا يعني قبول حفظ عملية مرتجعات بأوزان سالبة. شروط العملية، وزن الفارغ، وصافي الخرسانة موجودة في مشروع الموقع ولا تتغير بإعادة تنظيم برنامج القبان.
